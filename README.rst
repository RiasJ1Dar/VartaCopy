VartaCopy
=========

Копіювання та переміщення файлів і дерев каталогів для Windows на Rust: перевірка BLAKE3,
збережена черга, журнал і відновлення після переривання.

Ранній prerelease для Windows 10/11 x64. Основні випробування виконані на
локальній NTFS. Це робоча попередня версія, ще не реліз 1.0.

Незалежна реалізація
-------------------

Порівняння з TeraCopy спирається на спостереження за поведінкою та
незалежну реалізацію. Для попередніх етапів меню використовуються поведінкові
контракти формату ``specs/behavior-v1.schema.json``. У них окремо зазначені
спостережений результат і вимоги VartaCopy, включно з навмисними відмінностями.
``tools/cleanroom_gate.py`` перевіряє статус спостереження, окремий review та
SHA-256 доказів і формує контракт без сирих файлів чи шляхів до них.
Цей інструмент не створює ізоляції виконавців і не посвідчує їхню особу.
Код до ``005f8c0`` створений до запровадження цієї процедури; ретроспективна
відповідність суворому clean-room процесу для нього не заявляється.
Поточний обробник передачі розробляється одним виконавцем, який також проводив
дослідження; формальна ізоляція чорної й білої кімнат для нього не заявляється.
Реалізація використовує власні ідентифікатори, протокол і документовані API Windows.
Поточний контракт Explorer — ``specs/explorer-v2.json``; попередній V1
залишений для відстеження уточнень. Перші спостереження обмежені однією
папкою на локальній NTFS; це ще не підтвердження всіх сценаріїв Провідника.

Завантаження
------------

Готовий portable ZIP доступний у `Releases <https://github.com/RiasJ1Dar/VartaCopy/releases>`_.
Розпакуйте його в постійний каталог і запустіть ``vartacopy-gui.exe``.
Rust, Python, сторонні рантайми та права адміністратора для запуску не потрібні.
У ``alpha.2`` реєстрація обробника передачі потребує Python 3.11+.
У поточному коді до beta додані нативні кнопки увімкнення/вимкнення в
налаштуваннях і CLI ``integration status|check|install|remove``; Python для них
не потрібен. Inno Setup установник збирається командою нижче.
Готовність збірки установника не означає завершення його перевірки на Windows.

Установник
~~~~~~~~~~

Inno Setup 7.1+ створює майстер українською та англійською, ярлики й запис
видалення в Windows. Пункт вибору Explorer/VartaCopy позначений типово;
його можна вимкнути. Встановлення для всіх користувачів потребує UAC.
Оновлення використовує окрему DLL з версією та SHA-256 у шляху й не
перезаписує вже завантажений модуль. Активну VartaCopy потрібно закрити;
установник не завершує передачі або Провідник примусово.

Видалення перевіряє й прибирає власну реєстрацію до видалення файлів.
Якщо безпечне видалення інтеграції не підтверджене, файли залишаються
для відновлення встановлення. Історія й користувацькі файли зберігаються.
Докладна інструкція — ``packaging/explorer-transfer.rst``.

Збірка з перевіреного portable ZIP, зафіксованого в Git::

    python tools/installer.py --portable ARCHIVE.zip --iscc D:\Tools\InnoSetup-7.1.0\ISCC.exe --output D:\VartaCopy-build

Каталог результату має бути новим. Незафіксовані джерела блокуються;
``--allow-dirty`` призначений лише для локальної перевірки. Поруч з EXE
зберігаються SHA-256 та JSON зі складом пакета, revision і версією компілятора.
Установник не містить сертифіката видавця; виробничий Authenticode-підпис
залишається окремим етапом розповсюдження.

Можливості
----------

* Копіювання файла, кількох вибраних джерел або дерева каталогів, включно з порожніми каталогами.
* Переміщення через перевірене копіювання й окреме журналювання видалення джерела.
* BLAKE3 readback усіх підтриманих потоків, зокрема файлових NTFS ADS.
* SQLite-журнал, відновлення перевірених блоків і дерев за ідентичністю файлів.
* Збережена FIFO-черга, пауза, відновлення, історія, повторна перевірка й експорт JSON.
* Компактний GUI українською, світла/темна/системна та системна контрастна тема.
* Власна іконка програми, значок у системному треї та явне згортання у трей.
* Графік швидкості запису з текстовими показниками та окремий компактний вигляд передачі.
* Клавіатурна навігація, семантика Windows UI Automation, віртуальна таблиця.
* CLI та додаткове меню Провідника для файлів і каталогів; повторні запуски передають вибране до одного GUI.
* Експериментальний shell extension із вибором Explorer/VartaCopy при файловій передачі в Провіднику.

Вікно передачі
-------------

Значок VartaCopy з'являється у системному треї, поки GUI працює. Windows
може помістити його під стрілку прихованих значків. Натискання відкриває
вікно; контекстне меню має «Відкрити VartaCopy» та «Вийти».
«Меню» → «Згорнути у трей» приховує вікно й залишає передачу працювати.
«Вийти» та закриття вікна завершують роботу зі збереженням прогресу;
самостійного запуску у фоні немає. Після перезапуску Провідника значок
реєструється знову. Якщо трей недоступний, вікно залишається доступним.

21 жовтня 2026 року на Windows 11 x64 перевірено встановлення в Program Files,
повторне встановлення, вимкнення/увімкнення компонента, видалення й встановлення
назад. Власна COM-реєстрація прибрана при видаленні, історія збережена,
SHA-256 усіх встановлених файлів збіглися з пакетом. Запущена VartaCopy
блокує встановлення та видалення. Наступний запуск установника має дочекатися
повного завершення попереднього процесу, включно з його тимчасовим деінсталятором.

Кнопка «Компактний вигляд» відкриває невисоку панель зі шляхами, поточним
файлом, фазою, графіком та керуванням передачею. «Повний вигляд» повертає
попередній розмір вікна; подробиці й черга розкриваються окремо.
Зміна розміру відбувається за вашою дією.

Графік показує останні 30 секунд нових записів програми, включно з файловими
ADS. Повторне читання для перевірки та вже відновлені блоки не додаються
до записаних байтів. Це вимір швидкості запису через програму, а не фізичного
диска. Показник «До кінця потоку» стосується поточного потоку й доступний
лише за наявності виміряної швидкості та відомого залишку.
Завершення запису не означає завершення перевірки чи видалення джерела Move.

Графік останнього запуску зберігається в пам'яті до наступної передачі.
Новий запуск, зокрема відновлення, починає окремий облік; після перезапуску
програми попередній графік недоступний. Черга та історія завдань зберігаються
в SQLite незалежно від графіка.

Якщо новий запит передачі з Провідника не пройшов підготовку й не був
прийнятий у журнал, повідомлення прямо вказує, що копіювання або переміщення
не розпочато. Нова помилка відкриває вікно «Повідомлення»; найновіша помилка
показана першою. Попередній завершений запис в історії стосується свого
завдання й не підтверджує результат нового запиту.

Для помилки обробки вибору Explorer/VartaCopy поруч із журналом зберігається
один локальний файл ``jobs.sqlite3.last-transfer-error.json`` (для іншого
імені журналу — те саме ім'я з суфіксом ``.last-transfer-error.json``).
Він містить код Windows, час, версію, шляхи джерел і призначення та стан
прийняття запиту. Вміст файлів не записується, звіт нікуди не надсилається.
Наступний такий збій замінює попередній власний звіт; розмір обмежений 2 МіБ.
Якщо збереження звіту не вдалося, це зазначається в повідомленні.
Наявність прийнятого запиту або неможливість прочитати його стан потребує
перевірки журналу й файлів перед повтором; автоматичного повтору немає.

17 жовтня 2026 року на Windows 11 x64 перевірено компактний і повний вигляд,
графік під час копіювання тестового файла 512 МіБ, його збереження після
завершення та прокручування подробиць. SHA-256 основних даних і ADS у
джерелі та копії збіглися. Це перевірка поточної конфігурації; ширша матриця
DPI, тем і допоміжних технологій залишається окремим етапом.

Меню Провідника
---------------

У програмі: «Меню» → «Вигляд і правила…» → «Додати меню Провідника».
Після цього правою кнопкою виберіть «Копіювати через VartaCopy…», перевірте
список джерел, виберіть призначення та натисніть «Копіювати» або «До черги».

У Windows 11 команда знаходиться в «Показати додаткові параметри».
Інтеграція експериментальна. Якщо меню не оновилось, може знадобитися перезапуск Провідника.
Реєстрація цього додаткового меню стосується поточного користувача й сама
не змінює поведінку Ctrl+C/Ctrl+V. Окремий обробник передачі описаний нижче.
Вибір у Провіднику лише відкриває форму; копіювання потребує вашого підтвердження.

Для видалення: «Прибрати меню VartaCopy». Перед перенесенням або видаленням
portable-каталогу приберіть меню; з нового розташування його можна додати знову.
Через CLI: ``vartacopy.exe explorer install``, ``explorer status``, ``explorer remove``.

Сучасне меню Windows 11
~~~~~~~~~~~~~~~~~~~~~~

Окремий модуль ``vartacopy_explorer.dll`` реалізує команду
«Додати до VartaCopy…» безпосередньо в сучасному меню для однієї звичайної
локальної папки. Команда відкриває чернетку джерела; призначення та початок
копіювання обираються у GUI. Файли, множинний вибір, мережеві шляхи й reparse
points у цьому варіанті команди не підтримуються.

Для реєстрації потрібні sparse MSIX із довіреним підписом та постійний каталог
GUI/DLL. ``tools/modern_explorer.py`` збирає пакет, перевіряє його й надає явні
``status``, ``install``, ``remove`` для поточного користувача. Інструкція:
``packaging/explorer/README.rst``. Інструмент не додає сертифікати до довірених
і не перезапускає Провідник. Непідписаний пакет призначений для перевірки
збірки; для встановлення потрібен довірений підпис.

16 жовтня 2026 року на Windows 11 x64 перевірено появу команди в сучасному
меню, повторне доставлення джерела в один GUI, скасування, збереження історії,
явний запуск копіювання та видалення/повторне встановлення пакета.
Випробування виконані з тестовим сертифікатом і локальною NTFS-папкою.
Цей модуль ще не входить до опублікованого portable prerelease alpha.1;
виробничий підпис і ширша матриця Windows залишаються окремими етапами.

Вибір Explorer або VartaCopy
~~~~~~~~~~~~~~~~~~~~~~~~~~~

У формі нової операції вкажіть джерело, призначення та дію, потім натисніть
«Обрати Explorer або VartaCopy…». Вікно показує незмінний запит; закриття,
Escape чи «Скасувати» не додають завдань. Початковий фокус — на скасуванні.
Вставлення через кнопку «Вставити файли…» читає список файлів із буфера:
вирізані файли готуються для Move, скопійовані — для Copy. Вміст буфера
не очищується. Перетягування у VartaCopy з указаним призначенням відкриває
вибір; без призначення воно готує звичайну чернетку джерел.

Explorer виконує дію через ``IFileOperation`` зі стандартними діалогами Windows,
власними правилами конфліктів і скасуванням у системному вікні. Його результат
зберігається як звіт про спробу, без перевірки BLAKE3 та відновлення VartaCopy.
Варіант VartaCopy додає пачку до нашої черги з перевіркою; для цього вибору
наявна назва дає помилку, а посилання блокуються. Перед зміною обробника
через Explorer поточна передача має бути завершена або призупинена.
Запити VartaCopy можна додавати до збереженої черги під час її виконання.

Повний запит можна передати до того самого GUI через CLI::

    vartacopy-gui.exe --source C:\Source\file.txt --destination D:\Target --operation copy

``--operation move`` готує переміщення. Необов'язковий ``--request-id`` —
32 шістнадцяткові цифри, не всі нулі; при повторній доставці залишайте той
самий ID та вміст запиту. Підтвердження доставки означає приймання до вхідної
черги, а не початок передачі. Старий режим ``--source`` відкриває чернетку.

Цей вибір доступний у VartaCopy та для явних повних запитів. Окремий shell
extension додає вибір під час файлової передачі в самому Провіднику.
Встановлений раніше тестовий пакет сучасного меню та опублікована
``alpha.1`` цього обробника передачі не містять.

Обробник передачі в Провіднику (експериментальний)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

``vartacopy_transfer.dll`` реалізує окремий ``IShellExtInit`` / ``IContextMenu``
для файлових меню передачі. Він отримує джерела та призначення без читання
буфера обміну й показує вибір до виконання дії. Explorer залишає початкову
команду Windows; VartaCopy передає повний запит до нашого GUI з уже вибраним
обробником. Скасування використовує окрему команду без файлових операцій.
Автоматичного повтору або переходу до іншого обробника після спроби доставки немає.

Вікно вибору має компактне темне оформлення, окремі кнопки Explorer/VartaCopy
та початковий фокус на скасуванні. Повні шляхи доступні в текстових полях
лише для читання з клавіатурною навігацією. Системна контрастна тема
використовує стандартний діалог Windows. Оформлення застосовується лише
до нашого вікна й не змінює тему процесу Провідника.

Перевірено нативне читання ``IDataObject`` / ``CF_HDROP``, збереження UTF-16,
вибір стандартної команди меню, COM-ідентичність, завантаження Common Controls v6
і передавання вибраного режиму між процесами. ``Initialize`` утримує посилання
на ``IDataObject`` у тому самому COM apartment, не читаючи його формати;
джерела отримуються під час запиту меню передачі. ``CMF_DEFAULTONLY``
не читає джерел і не відкриває вибір.

19 жовтня 2026 року на Windows 11 x64 з локальною NTFS після явно дозволеної
реєстрації в HKLM перевірено звичайне Ctrl+C / Ctrl+V у Провіднику:
вибір з'явився, скасування не запустило передачу, а вибір VartaCopy завершив
копіювання тестового файла з Unicode-іменем. Джерело збережене, SHA-256
копії збігся, журнал містить одне завершене завдання й один запит.
Окремо через GUI перевірено Copy, Move та повторну доставку обох запитів:
дублікатів немає, зокрема після видалення джерела Move. Ліве перетягування
між тестовими папками на одному диску також перевірено в реальному Провіднику:
після вибору VartaCopy переміщення завершилося, джерело видалене, SHA-256
призначення збігся. Ця передача використала вже звичайний журнал користувача
з вимкненим діагностичним записом; у ньому одне завершене завдання Move.
Попередню реєстрацію пасивного обробника лише для користувача Windows
у цій конфігурації не викликала; наявність записів сама не доводить інтеграцію.
Починаючи з ``alpha.2``, DLL і засіб реєстрації входять до portable ZIP.
Встановлення описане в ``packaging/explorer-transfer.rst`` (``EXPLORER.txt``
у пакеті); кнопка звичайного меню в GUI його не вмикає.

Розробницька збірка й явна реєстрація для поточного користувача::

    cargo build --release --locked --target x86_64-pc-windows-msvc -p vartacopy-explorer-drop-probe --lib
    python tools/explorer_drop_probe.py install --handler transfer --dll D:\VartaCopy\vartacopy_transfer.dll --gui D:\VartaCopy\vartacopy-gui.exe --record D:\VartaCopy\install-transfer.json

Для окремої перевірки можна вказати ``--journal`` з абсолютним шляхом до нового
тестового журналу. Без нього GUI використовує звичайний журнал користувача.
Інструмент створює ``explorer-transfer.json`` поруч із DLL і лише
власні записи COM / ``DragDropHandlers``; він не підключає обробник до звичайного
меню папки. Чужі або змінені записи не перезаписуються. ``status`` читає стан,
а ``uninstall`` з тими самими DLL/GUI/journal перевіряє власність і прибирає записи
та конфігурацію. Кожен ``--record`` має вказувати новий файл.
``--scope machine`` потребує явного запуску з правами адміністратора; інструмент
не підвищує права, не змінює захист Windows і не перезапускає Провідник.
Саме машинна реєстрація використана в зазначеній перевірці Ctrl+V;
робота реєстрації лише для користувача не підтверджена.
Конфігурація розміщена біля модуля, щоб пакетна віртуалізація AppData
розробницького середовища не створювала окремі невидимі для Провідника копії.
Інструмент перевіряє фізичний шлях налаштувань. ``configure`` дозволяє
змінити власну перевірену конфігурацію; ``--diagnostics`` тимчасово вмикає
обмежений файл ``explorer-transfer-trace.jsonl`` біля DLL, без назв та вмісту файлів.

18 жовтня 2026 року в реальному GUI перевірено скасування без завдань,
копіювання дерева через обидва обробники, переміщення через Explorer та
повторний запит Move після зникнення джерела без повторного запуску.
Вміст, ADS і порожні каталоги звірено окремо. Виправлення шляхів із ``/``
для Windows Shell додатково перевірене нативними автотестами Copy/Move
для обох роздільників, файлів і дерев. Verbatim-шляхи зберігають точне
написання. Тести використовували окремий журнал і власні тимчасові дані.

Відновлення та межі
------------------

Після аварії відкрийте історію, виберіть перервану операцію й натисніть
«Відновити». Записані блоки перевіряються знову; старі завдання самі не запускаються.
Журнал зберігається в ``%LOCALAPPDATA%\VartaCopy\jobs.sqlite3`` на локальному
фіксованому диску. Власний журнал: ``vartacopy-gui.exe --journal PATH``.

Копіювання зберігає джерела. Переміщення видаляє їх лише після повторної
перевірки ідентичності, вмісту та підтриманих ADS джерела й призначення.
Очищення дерева йде від дочірніх елементів до батьків; нові сторонні файли
не видаляються. Цей режим потребує локальної NTFS із доступним TxF.
Якщо захист від одночасних змін недоступний, джерело зберігається,
а результат позначається як незавершений. Після збою між видаленням джерела
та записом підтвердження журнал може вимагати додаткової звірки: відсутність
старого імені сама собою не означає завершення переміщення.
Для продовження є явна дія «Відновити переміщення»; повторна перевірка Copy
не використовується для запуску видалення.

Переміщення та панель із графіком доступні починаючи з portable prerelease
``alpha.2``; попередній ``alpha.1`` цих можливостей не містить.
Приклади CLI::

    vartacopy.exe move C:\Source\file.txt D:\Destination --journal C:\Jobs\jobs.sqlite3
    vartacopy.exe enqueue C:\Source\Folder D:\Destination --operation move --journal C:\Jobs\jobs.sqlite3

Існуючі файли не перезаписуються, дерева не об'єднуються.
Політики конфліктів: помилка, пропустити або зберегти обидва. Пропуски дають
частковий результат. Reparse points типово блокуються; є явний режим пропуску.
ACL і власник успадковуються від призначення; directory ADS не підтримуються.

Пачка: до 512 джерел, спільний ліміт 100 000 елементів та 64 МіБ облікової
пам'яті плану. Класичне меню Windows обмежує множинний вибір до 100 елементів.
Черга показує перші 32 очікувані завдання; повний список доступний в історії сторінками.
Відновлення після process kill перевірене; гарантія фізичного power loss не заявляється.

Внутрішній журнал вибору обробника зберігає незмінний запит та вибір
Explorer або VartaCopy. Приймання запиту VartaCopy й додавання всієї пачки
до черги виконуються однією SQL-транзакцією; повторне доставлення повертає
ті самі завдання. Для Explorer окремо зберігаються намір запуску та результат
спроби. Непідтверджений намір після збою потребує звірки й не запускається
повторно автоматично. Окремий адаптер Windows використовує ``IFileOperation``
у STA, враховує скасування та повідомлення для окремих елементів. Це звіт
Windows про спробу, без незалежної перевірки BLAKE3. Вікно вибору використовує
ці механізми для явних запитів. Обробник Провідника передає до нього
запит із уже вибраним VartaCopy, без другого вікна вибору.

Для розробницької перевірки callback-механізму модуль також має окремий
пасивний CLSID. Його явний режим ``--handler probe`` не змінює меню
й не запускає передачу. Це окрема діагностика, а не режим встановлення
робочого обробника ``--handler transfer``.

Далі розробляються overwrite, повні Windows-метадані, керування швидкістю,
фільтри, checksum lists і глибша інтеграція з Провідником.
USB/SMB, Narrator/IME, системний text scale та multi-monitor DPI ще потребують матриці випробувань.

Збірка
------

Rust 1.95+ та MSVC Build Tools для x64::

    cargo build --release --locked --target x86_64-pc-windows-msvc --bin vartacopy --bin vartacopy-gui
    cargo test --workspace --all-features --target x86_64-pc-windows-msvc
    cargo clippy --workspace --all-targets --all-features --target x86_64-pc-windows-msvc -- -D warnings

Єдиний запуск перевірок (Python 3.11+) — ``python tools/check.py``:
форматування, Rust-тести, clippy та Python-тести. ``--offline`` використовує
лише кешовані Cargo-залежності. Інструмент фіксує ``--workspace --all-features``
для тестів і clippy, щоб обидві перевірки мали однаковий набір можливостей.

``python tools/package.py`` створює portable ZIP з manifest SHA-256,
ліцензією проєкту та notices залежностей. Готові пакети мають static CRT.
Вихідний код — MIT; ліцензії залежностей збережені окремо в пакеті.
