Вибір Explorer / VartaCopy у Провіднику
======================================

Модуль vartacopy_transfer.dll додає вибір перед файловою передачею через
Ctrl+V та перетягування. Explorer виконує стандартну дію Windows; VartaCopy
передає запит до нашої черги з перевіркою й журналом. «Скасувати», Escape
або закриття вікна не запускають передачу. Для цього вибору VartaCopy
існуюче ім'я є помилкою; посилання блокуються.

Перевірено Windows11 x64, локальну NTFS: Ctrl+C/Ctrl+V Copy, скасування
та ліве перетягування Move на тому самому диску. Це експериментальний
обробник; ширша матриця Windows, пристроїв і сценаріїв ще перевіряється.

Звичайний запуск vartacopy-gui.exe не потребує Python або адміністратора.
Для цього окремого способу реєстрації потрібен Python3.11+ і постійний
локальний каталог з EXE/DLL. Розпакування ZIP не реєструє модуль автоматично.
Це окремий механізм від кнопки додаткового меню у GUI й від sparse MSIX
для сучасного контекстного меню Windows11.

Встановлення
------------

Відкрийте PowerShell у каталозі з розпакованими EXE/DLL. Нижче D:\VartaCopy —
приклад; вкажіть своє фактичне постійне розташування. Кожен --record має
вказувати новий файл, щоб не перезаписати попередній звіт.

Спочатку перевірте стан::

    py -3 tools/explorer_drop_probe.py status --handler transfer --scope machine --dll D:\VartaCopy\vartacopy_transfer.dll --record D:\VartaCopy\status-before.json

Якщо стара версія вже зареєстрована в іншому каталозі, приберіть її її ж
інструментом і з її точними DLL/GUI шляхами перед новим встановленням.
Чужі або змінені записи інструмент не перезаписує.

Для машинної реєстрації відкрийте PowerShell від адміністратора й виконайте::

    py -3 tools/explorer_drop_probe.py install --handler transfer --scope machine --dll D:\VartaCopy\vartacopy_transfer.dll --gui D:\VartaCopy\vartacopy-gui.exe --record D:\VartaCopy\install-transfer.json

Саме цей режим перевірений на тестовому ПК. Режим --scope user не потребує
адміністратора, але спрацювання його обробника Провідник на тестовому ПК
не підтвердив. Інструмент не підвищує права сам і не перезапускає Провідник.
Якщо Windows уже завантажила попередню DLL, закрийте вікна Провідника
й перезапустіть його або вийдіть зі свого облікового запису та ввійдіть знову.

Налаштування explorer-transfer.json створюються біля DLL. Журнал за
замовчуванням — %LOCALAPPDATA%\VartaCopy\jobs.sqlite3. Діагностичний запис
типово вимкнений. Для встановлення цього обробника сертифікати й MSIX не потрібні.

Видалення
---------

До перенесення чи видалення каталогу приберіть реєстрацію з тими самими
шляхами й scope. Для машинної реєстрації знову потрібен адміністратор::

    py -3 tools/explorer_drop_probe.py uninstall --handler transfer --scope machine --dll D:\VartaCopy\vartacopy_transfer.dll --gui D:\VartaCopy\vartacopy-gui.exe --record D:\VartaCopy\uninstall-transfer.json

Якщо при встановленні задавали --journal або --diagnostics, передайте ті
самі параметри для перевірки власності налаштувань. Інструмент прибирає
лише власні записи COM/DragDropHandlers і конфігурацію; історія завдань
та скопійовані файли зберігаються. Завантажена DLL може залишатися зайнятою
до перезапуску Провідника.
